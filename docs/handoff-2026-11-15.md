# Handoff 2026-11-15: start of sf-agentic-sdlc

Status: working note for the next session (Claude Code on the owner's Mac).
Not normative. The normative files stay as listed in the README "Current authority" section.

## Goal

Build one agent system that runs through **GitHub Copilot CLI**. One prompt with a
requirement goes in. The agent system does the Salesforce development from the requirement:
design, implementation, tests, review, and a reviewable delivery packet. Humans keep the
decisions that must stay human.

## Decision: which project is the base

**Base: sf-extension-harness** (this repository, clean import of
`Vescik/sf-extension-harness` at `13a0e5481fcc2aafce3ba463514bc804c75e1a30`, 2026-10-05,
without history).

**Donor: W8-SDLC** (team W8 design ladder in the Deloitte "AI Native & Future Fit" programme:
`W8_SDLC/2_design/v0/` — A1 agent fit, L01–L10, workflow file). W8 is a design
specification with no Salesforce runtime. Its test data (OnePlace) is an Angular app.

Why the harness is the base:

- It runs today and it is Salesforce-specific: SFDX project, `force-app/`, Apex/Flow/
  managed-package instructions, reviewed `sf` deploy paths to `dev`/`uat`/`stage`,
  production read-only.
- It has requirement intake (`/fetch-ado-item`) and the roles designer → reviewer →
  developer → test-strategist.
- Its layout is Copilot-native: `.github/agents/*.agent.md`, `.github/skills/*/SKILL.md`,
  `.github/hooks/`, `.github/mcp.json`. Copilot CLI reads these locations.
- It has real controls: `scripts/copilot_safety_hook.py` (already handles the Copilot CLI
  shell tool name `Bash`), per-role guards, and 40+ test files.

## Gaps to close (the actual work)

1. **Port from VS Code to Copilot CLI** (largest item). Done 2026-11-15 in files and tests,
   live CLI check open: `docs/copilot-cli-port.md`. Original note: Agents declare `target: vscode` and
   VS Code tool names (`vscode/askQuestions`, `edit/editFiles`, `execute/runInTerminal`, the
   native VSIX `salesforceOperation` tool). Copilot CLI ignores unknown tool names silently,
   so an agent can load with missing tools. Move to the aliases `read`, `edit`, `execute`,
   `search`, `agent`, and decide the `target` value.
2. **Hooks.** Done 2026-11-15 (same file). Original note: `.github/hooks/safety.json` uses the VS Code shape (`PreToolUse`, `command`,
   `windows`). The Copilot CLI documented shape is `{"version": 1, "hooks": {"preToolUse":
   [{"type": "command", "bash": ..., "powershell": ...}]}}`. Agent-frontmatter `hooks:` are not
   documented for the CLI. Verify both on a live CLI.
3. **Orchestrator.** Done 2026-11-15 as an SDK host, live run open: `docs/orchestrator.md`. Original note: No agent today runs design → review → implement → test → review →
   packet from one prompt. Add one that calls roles as sub-agents and carries the W8 ticket.
4. **Autonomy policy.** Decided 2026-11-15: retrieve, validate and deploy to `salesforce.agentOrg`
   without a fresh question in orchestrated runs (SAFE-DEPLOY-AUTONOMY-001); human checkpoints
   H1–H3 as in W8. Original note: The harness asks for a fresh confirmation before every non-prod deploy
   and needs an explicit instruction for push/PR. Define what one prompt authorizes (for example
   full freedom in a scratch org or `dev`, a draft PR) and keep the human gates from W8.
5. **MCP for the CLI.** Done 2026-11-15 (same file). Original note: `.github/mcp.json` has no server (the Knowledge server was removed on
   2026-11-15). Salesforce review and ADO are configured for VS Code only (`.vscode/mcp.json`).
6. **Trim for the MVP.** Done 2026-11-15: the Knowledge subsystem (entries, Feature Knowledge,
   search, force-app inventory, its MCP server, curator agent, prompts, skills, schemas and
   tests) is removed. ADO Feature delivery and Feature Health stay. Release handover was
   removed on 2026-11-15; wiki publication stays by owner decision.

## First step: spike (1–2 hours)

Run Copilot CLI in this repository with one agent (designer) and record:

1. Does an agent with `target: vscode` load in the CLI (`/agent`, `/env`)?
2. Does `.github/hooks/safety.json` fire in its current shape? Test: a command the hook must
   deny, and check the hook decision in the CLI output or log.
3. Which tools does the agent actually get?

The result decides whether the port is cosmetic or a rewrite of the agent layer.
After the spike: map W8 stations S1–S8 to the harness agents and write the orchestrator
contract.
